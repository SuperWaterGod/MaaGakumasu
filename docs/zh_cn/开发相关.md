# MaaGakumasu 开发相关

MaaGakumasu 主要基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 框架开发。

选择 `JSON + 自定义逻辑扩展` 模式

请先阅读MFW官方文档，了解MFW的使用方法。

## Python 模块组织

培育运行时业务统一放在 `agent/produce/`，MaaFramework 动作入口在 `agent/custom/action/produce.py`，识别回调在 `agent/custom/reco/produce.py`。`agent/utils/` 仅保留通用日志和图像接口，项目维护脚本放在 `tools/`，培育训练、实验与回归代码集中在 `research/produce/`。

| 模块 | 职责 |
| --- | --- |
| `events.py` | 初/NIA 事件策略及共享事件基类 |
| `battle.py` | 出牌、饮料、候选记录、计时和超时兜底 |
| `options.py` | 工作、属性、试镜档位、饮料保留等选项 |
| `catalog.py` | 技能卡、饮料、P 道具身份查库与结构化参考数据 |
| `rewards.py` | 奖励候选布局、预览/恢复、详情及图标缓存、后台读取 |
| `capture.py` | 异步事件/截图写盘、后台进程与摘要回传 |
| `sessions.py` | 整轮会话、继续/跳过准备、中断收尾及框架 sinks |
| `state.py` | 战斗数值、Buff、姿态等可见状态识别 |
| `settlement.py` | 结算标签/图标定位、最终评价分数/评级与三维读取，初/NIA 公式校验；不依赖评级模板 |
| `analysis.py` | 无输入的后台 OCR、手牌与路线分析，提供脚本入口 |
| `console.py` | 出牌、奖励与结算的事件聚合、顺序、状态显示及库效果文案 |

新代码先放入已有职责模块，不按每个 helper、类型或常量新建文件。短小且只有一个调用方的逻辑通常并入调用方；真正独立的接口、生命周期或需要分别验证的逻辑再拆。约 100 行以下的辅助文件优先检查合并，约 700 行以上的模块优先检查职责，均不作为硬性行数要求。奖励采集和培育动作遵守相同标准，避免一边碎片化、一边不断堆叠大文件。

培育实验代码放在 `research/produce/`：`capture_battle.py` 是独立采样入口，`report_produce_session.py` / `report_decision_capture.py` 加载证据并生成报告，`produce_reporting.py` 负责完整性审计、过程摘要和跨轮统计，`replay_reward_effects.py` 重放已有奖励 OCR，`build_buff_templates.py` 从实验样本取模板，`test_reporting.py` 使用合成数据做离线回归。具体入口和目录边界见 [research 说明](../../research/README.md)。实验输出、真实截图和一次性脚本继续保存在 Git 忽略的 `debug/`。

`agent/produce/analysis.py` 由客户端采集器启动，承担运行时后台识别及日志输出，因此继续放在 Agent 内；正式技能卡、奖励库同步脚本生成客户端资源，继续放在 `tools/`。客户端不依赖 `research/`，现有发布包不包含该目录。

内部使用包导入；后台工作进程直接启动 `agent/produce/analysis.py`，入口为内置 Python 设置 `agent/` 路径，内部不使用多套裸模块导入。`produce/__init__.py` 不自动注册动作或安装监听，只有框架入口显式导入注册类。运行链不依赖 Pillow。

整理文件时同步修改调用方、维护工具、源码指纹及文档，清除旧源码和旧字节码；保留原事件、数据库和历史报告。更详细的协作规则见根目录 `AGENTS.md` 的“模块组织与拆分规范”。

### 出牌数据标注与验证

出牌模型使用互斥类别：普通可用牌标为 `cards`，推荐牌标为 `recommend`，不可用牌标为 `useless`。同一卡牌仅标一个类别；不同卡牌因遮挡产生的重叠框仍需保留。MaaFramework 会对不同类别的重叠框一起去重，因此不要在同一张推荐牌上同时标注 `cards` 和 `recommend`。

训练完成后，应通过实际使用的 MaaFramework 版本验证导出的 ONNX，确认最终检测结果，并覆盖无推荐牌、多牌遮挡、不可用牌、无手牌和动画过渡场景。训练指标不等同于实际出牌成功率。

出牌超时截图收集、候选导出和临时规则对比工具已移除。15 秒未识别到推荐牌时的兜底出牌逻辑继续保留；排查问题可保存 `debug/maa.log`，并使用模拟器截图工具收集原图，人工复核后在 Roboflow 标注。已有调试截图和训练素材不会自动删除。

截图样本建议使用 `MuMu模拟器12` 自带截图工具，出牌原图宽 720、高 1280（240DPI）；标注和验证时保持原始方向与尺寸。

### 对局信息采集与技能卡匹配

开发中的对局采集模块可记录出牌前后画面、手牌检测与实际操作，并在独立进程中用 MaaFramework OCR 匹配固定版本的技能卡库、读取剩余回合和可见战斗数值。采集统一保存为 720×1280；手牌支持前缀匹配，Buff 使用框架原生绿幕模板匹配与 OCR，包含好调/绝好调回合数与集中效果提升百分比，另行读取非凡强气/温存姿态、阶段、全力值和指针预告。同位置 Buff/姿态候选会比较证据；明确登记的集中图标亲缘候选可用整数/百分比区分，单位冲突或模板歧义保留未知。培育会话关联中断分段、路线候选、选择输入和结算观察，报告汇总跨分段结果。完整开局牌组、实际扣费/库存变化及更多布局仍需独立证据。识别不确定的牌名、强化、隐藏状态与改造保留未知。控制台将同一操作前后的状态、手牌、变化和耗时合为一条默认折叠日志，按逻辑操作连续编号；原始事件编号仍保留。卡库参考效果不等于当下实际收益。启用方式、覆盖限制与旧数据补处理见 [出牌数据采集](出牌数据采集.md)，采样方法见 [出牌状态采样计划](出牌状态采样计划.md)；具体轮次、截图来源和验证报告保存在 `debug/`。
