# 出牌数据采集

当前提供两种模式：正在运行的 MFA 可用只读 ADB 旁路采集；beta 的 Agent 可启用操作事件采集。现有出牌策略保持原样。

## Agent 操作事件采集

将采集版本部署到测试包的 `agent/`，并在测试包的 `config/decision_capture.json` 写入：

```json
{
    "enabled": true,
    "match_cards": true,
    "console_summary": true,
    "max_bytes": 2147483648,
    "min_free_bytes": 536870912
}
```

配置不存在或 `enabled` 不为 `true` 时关闭。每次进入 `ProduceCardsAuto` 读取配置，创建一个独立采集目录。已启动的 Python Agent 不会因复制代码自动更新，需要在任务安全结束后重新加载 Agent。

记录内容：进入/退出观察、YOLO 全部候选及手牌区域过滤标记、推荐/单牌/超时选牌原因、选中框、两次底层点击、饮料任务、跳过、移动卡牌与确认弹窗、返回可操作状态或退出后的截图。两个点击归属于同一个逻辑操作。

截图直接复用框架图像，按 BGR 转 RGB 后保存，不旋转。主数据统一为竖屏 720×1280；异常宽高比保留实际尺寸并标注，不强行旋转。检测置信度不是卡牌收益。`decision_after.game_action_confirmed` 暂为 `null`，返回可操作状态不能独立证明牌已打出。

存在本地技能卡库时，默认同时启动独立的卡牌分析进程。它只读取截图与事件，使用没有物理输入能力的离线 Maa 控制器执行检测/OCR，不向 MuMu 发送操作。`match_cards: false` 可关闭后台分析。采集与分析异常各自记录，不阻塞培育。

默认将后台摘要回传到 MFA 控制台，包含采集启动、手牌名称、推荐/普通/不可用分类、匹配或待确认状态，以及选中牌的记录。牌名解析会稍晚于实际操作，日志用“操作前/操作后”和事件序号标记来源；连续相同手牌摘要不重复输出。`console_summary: false` 可关闭摘要，完整信息仍保存在文件中。已加载旧代码的 Agent 需要在本轮结束后重新启动客户端，新日志才会生效。

采集器使用有界后台队列保存文件。达到体积/磁盘限制或写盘失败时停止采集，游戏任务继续；丢弃及错误写入清单。进程异常退出可能留下未完成目录，不能视为完整对局。

## 当前任务的 ADB 旁路采集

在仓库中使用已安装的 Python、Pillow、OpenCV 和 NumPy。它们来自当前开发/框架环境，不需要新增 LLM 服务。先用 `adb devices -l` 确认设备，仅指定一个实例：

```powershell
python tools/capture_battle.py --adb D:/MuMuPlayer-12.0/nx_main/adb.exe --serial 127.0.0.1:16384 --output D:/Projects/MaaGakumasu-beta/debug/decision_capture --resource D:/Projects/MaaGakumasu-beta/resource/base
```

仅执行 `exec-out screencap -p`，不发送点击、不另建游戏控制器。默认每 1.5 秒观察，体力和跳过按钮同时匹配时保存出牌帧，并保留短暂过渡帧。第一帧用于诊断；出牌动画或特殊界面可能漏采。

ADB 截图在写盘时统一缩放到 720×1280，记录来源尺寸与是否缩放；旧版本已保存的设备原分辨率截图保留。`battle_hint` 是模板判断，不能直接作为可信场景标签。横屏或不兼容布局不会强行旋转匹配。

旁路采集默认从资源包的 `data/produce_skill_cards.json` 读取卡库；`--database` 可指定其他路径。`--no-card-analysis` 仅采集画面。独立分析使用本地 MaaFramework、NumPy 和 Pillow；beta 的内置 Python 已补齐 Pillow。

默认运行上限一小时，连续十五分钟未发现出牌场景时停止；连续三次截图失败或达到写盘限制也停止。每次采集的 `observer.json` 包含 PID 与停止文件路径，在该目录创建空文件 `STOP` 即可停止。`observer_status.json` 提供最新采样时间、原始尺寸和匹配结果。

## 输出与报告

保存位置为运行包的 `debug/decision_capture/<run_id>/`：

- `manifest.json`：模式、版本、限制、状态、丢弃数和未知字段。
- `events.jsonl`：带顺序、时间、关联操作 ID 的事件。
- `frames/`：PNG 原图，按 SHA-256 去重。
- `derived/card_identity/<analysis_id>/`：每帧手牌、OCR 证据、卡库匹配、事件关联索引与处理状态。
- `report.md` / `report.json`：事件数量、缺帧、操作配对和未知项。

旁路结束时自动生成报告；Agent 记录或仍在运行的目录可生成阶段报告：

```powershell
python tools/report_decision_capture.py D:/Projects/MaaGakumasu-beta/debug/decision_capture/<run_id>
```

当前已加入牌名、卡库身份与可见强化标记的匹配。Buff、回合、分数与体力数值尚未自动解析，字段保持未知。现有自动逻辑的操作不等于最优策略标签。没有完整路线和开局信息时，不宣称已还原完整培育。

## 技能卡数据库与身份匹配

`assets/data/produce_skill_cards.json` 独立于偶像歌曲卡库，保存上游原始字段、效果 DSL、提交 SHA、文件校验值及抓取时间。本次快照包含 908 条记录（含强化版），来自 `gakumas-tools/gakumas-tools`；再分发声明在同目录 `GAKUMAS_DATA_LICENSE.txt`。

更新时显式指定经过核对的上游提交，不在培育中自动联网更新：

```powershell
python tools/sync_skill_cards.py --revision <40位上游提交SHA>
```

Maa YOLO 定位手牌后，对卡牌底部名称做 OCR；Agent 采集优先复用当时检测框，旧的旁路截图在离线分析时重新检测。名称做 NFKC 和空白/标点归一化，保留 `+`，再匹配对应基础/强化条目。

多卡重叠时，同时检查原名称区域和按右侧相邻卡牌收窄的可见区域。完整卡库名称已出现且尾部只混入一至两个字符时，允许清理相邻文字。牌名被截断时，在存在遮挡证据、可见前缀至少三个字符且覆盖候选名称至少 60% 时，匹配最相近候选；基础版与强化版按同名归组。如果多个不同牌名共享可见前缀，则仅保留相似度候选，不因其中一个名称更短就确认身份。原 OCR、匹配依据和两种区域的结果全部保留。

基础牌名识别独立于强化信息：前缀匹配或遮挡区域未读到 `+` 时，仍给出基础牌名，强化状态保留未知，不阻塞基础身份使用。不同区域若指向不同卡名则保持未知；若卡名相同而强化标记不一致，则标记牌名已匹配、强化待确认，不把多余 `+` 静默丢弃。当前采集优先覆盖牌名和状态，强化解析为后续收益计算保留证据。

- 输出卡牌 ID、原名、流派、强化标记、OCR 置信度、名称相似度、备选条目和 `reference_effect_dsl`。
- OCR 置信度不足、前缀过短或候选接近时返回未知，不强制选一个 ID。名称相似度与前缀覆盖程度都不是校准后的概率。
- `++` 等额外标记记录为 `base_match_variant_unresolved`，可给出基础强化条目，但不把额外变化当作已解析效果。
- 自定义改造与局内临时变化尚未从画面解析，因此 `effective_effect_dsl` 保持未知；卡库效果只是参考，不能当作当下实际收益。
- 当前上游名称以日文为主；汉化名需提供经过核对的 `data/skill_card_aliases.json`（仓库布局为 `assets/data/`），结构为 `{"卡牌source_id": ["别名", "别名+"]}`。升级版别名应填在升级条目的 ID 下。未覆盖汉化名保持未知，不自动翻译后强行匹配。

对已采集的旧数据补做匹配，不修改原始事件：

```powershell
python agent/utils/card_analysis.py --capture-dir D:/Projects/MaaGakumasu-beta/debug/decision_capture/<run_id> --resource D:/Projects/MaaGakumasu-beta/resource/base --database assets/data/produce_skill_cards.json
```

分析结果按卡库、模型、匹配代码与 Maa Python 包版本区分目录。`index.jsonl` 将事件 ID 与结果文件关联；`status.json` 包含进度、匹配/未知数量和错误。运行期间使用 `--follow` 持续读取新增事件；采集关闭后处理完现有事件即结束。采集器定期更新心跳，在路线/事件阶段等待下一场出牌时分析进程继续等待；没有新事件超过两分钟且采集心跳失效时才结束。

采集素材均位于 Git 忽略的 `debug/` 内，应保留，不能作为源代码提交。后续识别结果应另存派生数据，保留原始观测。
