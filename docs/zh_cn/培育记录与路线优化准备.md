# 培育记录与路线优化准备

## 当前能力

快速模式默认开启；关闭后启用过程记录、同步识别和 HTML 回放。截图由独立开关控制，默认关闭。完整模式支持中断续跑，快速模式期间不记录，重新开启时建立部分会话。

奖励使用上游图库匹配，必要时预览详情并 OCR 名称，随后按配置选择并核验领取。识别结果用于日志和研究，当前仍沿用原有事件与出牌策略。

使用方法见 [功能说明](功能说明.md)，识别和接口细节见 [开发相关](开发相关.md)，离线命令见 [出牌数据采集](出牌数据采集.md)。

## 模块边界

- Pipeline：识别、输入、跳转、等待、重试及通知。
- 业务模块：事件、选项、出牌和奖励逻辑及决策记录。
- `sessions` / `capture`：会话关联、事件与截图保存。
- `reporting` / `audit`：单轮回放与证据审计。
- `research`：独立采样、离线报告与跨轮统计，复用运行时读取器。

实际观测与策略兜底值分别保存，未知值不填零。游戏效果与输入结果分别记录。

## 记录目录

完整模式每局目录为 `debug/produce_sessions/YYYYMMDD_HHmm_难度_偶像_歌曲/`，同名时追加数字序号。用户打开 `report.html` 即可查看回放；分享带截图的报告时，一并保留 `data/`。

### 文件用途

| 位置 | 用途 |
| --- | --- |
| `report.html` | 用户可读的 HTML 回放 |
| `data/session.json` | 整局身份、开始结束时间、续跑分段清单 |
| `data/report.json` | 仅离线分析命令显式导出；客户端不重复保存 |
| `data/report_status.json` | 报告是否完成、是否已经提醒、处理异常 |
| `data/report_pending.json` | 未完成报告的待办标记，完成后移除 |
| `data/01/manifest.json` | 该运行分段的采集状态、截图设置、数量与缺口 |
| `data/01/events.jsonl` | 按时间追加的原始操作和观测，是重建报告的依据 |
| `data/01/frames/` | 开启截图记录时留存的画面；关闭时不创建图片目录 |
| `data/01/analysis/results.jsonl` | 一条结果流同时保存事件关联与识别结果；同画面引用复用，不再每图生成 JSON 和独立索引 |
| `data/01/analysis/status.json` | 同步识别状态与统计，用于判断报告是否完整 |

`01`、`02` 表示中断续跑的运行分段。同场战斗合并展示，截图集中放在表格下方。待生成或待通知的报告在本进程首次进入完整模式时补处理。当前读取 schema 4。

## 路线优化顺序

1. 用完整会话建立基线，统计完成率、重试、评分、三维、票数和耗时，按配置及源码版本分组。
2. 优先研究体力、休息和属性路线，未知状态沿用原策略。
3. 奖励选择先做离线比较，再评估是否接入实时决策。
4. 出牌优化补齐目标流派所需状态，并保留推荐优先与超时兜底。

当前尚未实现策略训练。后续重点验证初/NIA 连续多局、中断恢复、失败重试、活动奖励及结算记录，并分段测量识别和操作耗时。
