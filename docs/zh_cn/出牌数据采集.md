# 培育记录与离线采集

本文描述当前实现。目录与路线图边界见 [培育记录与路线优化准备](培育记录与路线优化准备.md)，开发职责见 [开发相关](开发相关.md)。

## 客户端记录

快速模式默认开启，不创建培育记录。关闭后，正式进入培育循环才建立会话；准备阶段暂存证据。“开启截图记录”默认关闭，仅控制画面留存。首次使用完整模式前需执行“更新数据库和素材”。偶像之路等非培育调用仍由高级配置的 enabled 控制。

以下记录与识别说明适用于完整模式。

可选配置位于 `config/decision_capture.json`，培育任务仍优先遵循快速模式开关：

```json
{
    "enabled": true,
    "match_cards": true,
    "console_summary": true,
    "console_details": true,
    "reward_preview": true,
    "reward_identity_cache": true,
    "max_bytes": 2147483648,
    "min_free_bytes": 536870912
}
```

修改配置或源码后，需要在当前任务安全结束后重新加载 Agent，运行中的 Python 不会自动更新。

Pipeline 继续负责识别、简单点击、跳转、重试和等待；已有 Custom 动作处理复杂业务。记录监听器不代替流程引擎。推荐优先、有效手牌区域过滤和 15 秒兜底继续保留，记录结果不自动改选策略。

## 图像、识别与耗时

客户端使用当前回调的 MaaFramework Context 和内存 BGR 图像同步识别，Context 每次显式传入。离线工具自行创建无物理输入的识别环境。

关闭截图时仅保存文字与识别结果；开启时使用 MaaFramework 原生 PNG 编码保存原尺寸画面。达到容量或剩余空间限制时停止留图并记录原因。

战斗只保存操作前画面，下一次操作前观测也作为上一操作的后续观察，图片与识别结果引用复用。最后一次操作缺少后续画面时标为未知，不补拍冗余截图。已取得的手牌检测候选直接复用。

出牌标题时间从选择窗口开始到第二次点击完成，包含截图、手牌识别、等待推荐、同步状态/牌名识别及记录，不含后续动画等待。

## 控制台与回放

- 路线：Pipeline 绿色进入提示，然后输出“选择某事件”的折叠决策；状态分短行，候选编号，箭头标记本次选择。
- 奖励：进入页面提示，然后输出“已点击领取”的折叠详情；候选使用同样的箭头，附模板匹配、OCR 匹配及新增缓存数量。
- 出牌：完整模式使用折叠日志，标题显示操作编号、牌名及耗时，展开查看手牌、状态、Buff 和变化。快速模式使用单行提示。
- 移动／复制选牌：快速与完整模式均输出进入和确认提示，确认失败时明确提示未完成；按已有页头图标区分移动、复制，类型未确认时显示“移动／复制”。
- 纯 Pipeline 操作保持普通 focus，异常、手动接管及系统通知保留原机制。

会话目录为 debug/produce_sessions/YYYYMMDD_HHmm_难度_偶像_歌曲/，使用开局本地时间；非法字符清理，同名目录按需增加数字后缀。内部会话身份稳定，续跑增加 data/02 等分段，不因迟到识别重命名。

客户端只生成用户回放 report.html，不另生成 Markdown 或重复的 report.json。后者仅在研究 CLI 显式导出时保存。正常完成、失败终止或中断时同步收尾并提示报告链接；未生成成功的已关闭会话保存待办，在本进程首次进入完整模式时补处理。

回放按事件组织，一场战斗一张表。奖励、工作和属性选择不显示空的“观察变化：未确认”。强化、删除／复制／变换的流程输入纳入回放，当前不保证识别具体卡名或确认实际效果。

使用浏览器离线打开 HTML 报告，截图默认收起，点击“查看截图”展开，再次点击收起；点击图片可查看原图。样式内置，无需联网；分享含截图的报告时需一并保留 data/ 目录及其相对位置。没有截图时不输出空折叠区或失效图片链接。

## 奖励身份与图标

奖励优先只读匹配 `data/images/{skillCards,pDrinks,pItems}/*.png` 中的上游原图；没有 `icons/` 子目录。完整模式先识别奖励候选，匹配失败时有限预览详情并读取名称 OCR；随后按「卡片选择优先级」选择，核验最终选中项后领取。名称 OCR 只读取名称，识别结果关联卡库中的静态效果参考。强化或改造状态不明时保留未知。

图片由“更新数据库和素材”子任务下载，也可手工准备。图库不再从截图学习、不生成模板或磁盘缓存索引；历史 `debug/cache/reward_identity/` 材料保留，但不用于新匹配。缩放、遮罩和特征仅驻留内存。更新过程、扁平目录和部署方式见 [培育资源更新](培育资源更新.md)。

商店、强化、删除／复制／变换、移动页面只匹配当前可见图标，身份或版本有歧义时保留未知。

当前识别范围为单排 2–4 个候选，活动布局仍需补充实机验证。领取前核验页面、点击位置与最终选中项，失败时暂停领取。

## 状态与结算

体力、三维读取共用解析；实际零值与未知分开，策略兜底另存。路线三维常规读取失败且上限已识别时，才补读排除图标的数值区域。战斗 Buff 使用 MaaFramework 模板与 OCR，冲突和单位不明保留未知。

结算按页面文字标签及已校验属性图标定位，不为各评级单独建模板。初与 NIA 的公式值、实测值分开记录；总分、考试分数、票数不能混用。翻页证据沿用现有输入，只在明确 Next/生成/完成按钮处等待稳定；结束循环无条件点击兜底保留。

## 研究与离线工具

研究入口见 [research 说明](../../research/README.md)。客户端不能依赖 research，研究工具复用客户端识别、单轮报告与审计，不复制运行时实现。

```powershell
python research/produce/report_produce_session.py <会话目录> --output ../MaaGakumasuLab/debug/research/produce/report
python research/produce/report_produce_session.py <会话根目录> --all --output ../MaaGakumasuLab/debug/research/produce/summary
python research/produce/report_produce_session.py <会话目录> --refresh-settlement --resource assets/resource/base --output ../MaaGakumasuLab/debug/research/produce/report
python research/produce/analyze_choices.py <研究报告根目录> --output ../MaaGakumasuLab/debug/research/produce/baseline
```

结算重读只处理已保存截图，不连接设备，结果单独保存供报告使用。截图关闭时无法重新识别未留存的图像。跨轮统计不证明策略收益；版本信息缺失时必须保留未知。

capture_battle.py 是显式启动的只读 ADB 旁路实验，与客户端整局记录不同；report_decision_capture.py 为其单段摘要，仍有实际调用。参数查看 --help。实验截图、临时脚本和验证产物放入相邻 MaaGakumasuLab/debug，beta 原始运行记录留在 beta。

实机验证重点为初/NIA、连续多轮、中断续跑、活动奖励、失败重试和结束提示。

## 课程、考试和试镜布局

HUD 根据实际画面区分课程与考试/试镜，不按配置难度强行套坐标。课程读取剩余回合、体力、元气，支持 `0+2` 等追加回合显示；不把中央的 CLEAR/PERFECT 距离当作考试总分。初的考试与 NIA 试镜保留排名栏玩家定位、属性和倍率读取。REGULAR/PRO/MASTER 同类页面复用读取器；不同难度并不意味着画面所有字段都相同，未验证的特殊布局仍保留未知。

初的排名页按玩家行独有的日志按钮定位分数和名次，待同一场结束窗口出现左上角“最终考试”标签后才用于公式校验。新战斗、重试会清空待关联排名，避免把中间考试结果当最终考试；NIA 不使用这条初考试关联。运行时与离线结算重读使用同一实现。

课程通过页面标签和至少两个可信数值确认 HUD；单个字段未读准时保留其他结果。

初和 NIA 均在每场出牌结束后旁路记录结果翻页，直到下一场战斗、路线、奖励或准备/主页入口，覆盖评分页先于回忆生成出现的路径；新战斗、路线或奖励开始时关闭结果采集窗口。失败轮次仅记录实际出现并识别到的评分，不以最后一次出牌前分数冒充最终分数。

“继续培育”与“跳过准备阶段”均支持接续配置匹配的未完成记录；上一局已结束、已观察到结算或终止节点时，新建记录，不重新接上上一局。从主界面开始或实际进入难度选择时，旧活动会话先收尾，新局到正式培育入口才建立记录；结算后返回循环或主页也会关闭上一局。同偶像、同歌曲不是续跑依据。异常退出的历史记录保留，不自动并入从头开始的新局。

记录器不改写 Pipeline 的节点跳转、重试或培育次数。考试失败与重试仍属于当前局，仅观察原流程的结束节点进行收尾。结果采集不再以固定点击次数截断，减少动画与最终评价页之间的采集空档；是否读到分数仍取决于现有识别画面。结束、生成和完成三个结算出口统一经 `ProduceBackHome` 返回次数判断，避免直接跳到准备入口绕过 `ProduceLoop.max_hit`；实际次数仍由 Pipeline 控制。
