# 培育记录与路线优化准备

## 相对主线的功能

本次以 decision-capture 的采集能力为基础，协调主线已有的演出跳过、生成按钮识别和 Roar 卡片更新。主线修复与采集扩展分别保留，Pipeline 继续控制流程。

| 能力 | 原采集分支 | 本次整合 |
| --- | --- | --- |
| 出牌和状态 | 出牌前后、手牌、Buff、结算识别 | 保留识别及原策略，接入整局时间线 |
| 会话记录 | 配置文件开启，UUID 目录，支持续跑 | 文字常开，目录按时间、偶像、歌曲命名，续跑身份不变 |
| 截图 | 与采集整体启停绑定 | 任务开关独立控制长期保存，默认关闭；直接识别内存图像 |
| 回放 | 研究 CLI 手动生成 | 单轮核心下沉，同步收尾及重启补处理 |
| 奖励缓存 | 采集分段内学习 | 按卡库和布局等指纹跨局复用，系统锁协调并发写入 |
| 日志 | focus 与 Custom 详情分散 | 保留原生 focus；已有 Custom 摘要折叠，回放统一时间线 |
| 状态解析 | 事件与选项重复解析 | 共享体力、三维读取，保留页面布局，未知与策略默认值分开 |

## 文件与接口边界

- Pipeline：识别、简单输入、跳转、等待、重试、原生通知与手动接管。
- 业务模块：原有事件、选项、出牌和奖励逻辑；只有已有复杂动作记录内部决策细节。
- sessions/capture：旁路事件记录、会话关联、截图生命周期，不指挥游戏流程。
- reporting/audit：单轮汇总、证据审计和自动回放；研究 CLI 复用，不复制第二套实现。
- research：跨轮统计、离线建议和回归实验，客户端不依赖此目录。

观测字段保存实际值、来源、时间和未知原因；旧策略使用的默认值保存在独立字段。点击成功与游戏效果确认分开，当前仍不确认完整持有库存、实际扣费及所有动作收益。

## 新路线图的接入顺序

1. 复用会话报告做基线：完成情况、重试、最终评分、三维、票数与耗时。缺失指标不填零，配置及版本不同的样本分别统计。
2. 新规则仅使用可信、属于当前决策画面的状态；未知时沿用原策略。先研究体力、休息和属性路线，不增加完整牌组系统。
3. 奖励优化先做离线建议。当前同步识别结果不是实时策略接口，不允许直接使用可能过期的结果改选。
4. 出牌优化另行补齐目标流派必要字段，保留推荐与超时兜底；本次没有实现新的出牌规则。

本次未加入策略改选、模型训练、全卡模拟、HIF 或 LEGEND。跨局缓存用于减少识别开销，不代表策略收益提升。

## 验证说明

可复用回归在 `research/produce/test_reporting.py` 与 `test_recording.py`，使用合成记录和图像；实验验证证据保存在相邻 `MaaGakumasuLab/debug/`，客户端正常运行记录留在对应客户端。完整游戏流程、NIA/初的实际耗时和跨设备行为需要在加载新 Agent 后验证，离线测试不能替代实机验收。

## 记录目录与控制台展示

每局目录命名为 `YYYYMMDD_HHmm_难度_偶像_歌曲`，不带随机字符；同一分钟同名时追加 `_2`、`_3`。完整日期、时区和内部会话 ID 存在清单中。

```text
20261028_0130_偶像_歌曲/
  report.md            Markdown 回放
  data/                原始记录与识别状态
    session.json
    01/                第一次运行
      events.jsonl
      frames/          完整截图，不是图标切片
      analysis/
    02/                中断后继续运行（仅实际续跑时出现）
```

截图开关开启时，各事件附上已保存的关键截图，战斗仅附操作前截图；关闭时保留文字和识别结果，全图只在内存中处理，不写临时文件。原始记录是生成回放、排错和离线分析的依据，统一收在 `data/`，不再在入口散落后台文件。当前测试格式为 schema 4，不读取或迁移旧格式，也不删除已有记录。

奖励图标集中在客户端的 `debug/cache/reward_identity/icons/`，清单保存在其父目录。格式、卡库和布局不一致时重新学习，不建立指纹子目录。

已有 Custom 动作与同步识别默认输出折叠日志，标题为“当前事件－实际操作”；奖励展示候选名称和选中项，仅未匹配时附提示；路线、工作和试镜展示当前状态，路线补充可选事件，试镜门槛从低到高以连字符排列，属性使用声乐、舞蹈、形象名称，省略坐标和策略兜底，使用单个 HTML 根元素和逐行正文。普通 Pipeline focus 保留单行提示。工作子动作已打印实际选择时，不再重复打印父路线完成提示。折叠标题字重由客户端决定；配置 `console_details=false` 仅显式隐藏详情，默认开启。

用户回放每个事件独立成表；同场战斗按战斗调用 ID 合并为一张表，每行展示一次出牌、饮料或回合操作的手牌、选择、依据和变化，截图集中放在该场战斗下方。考试重试或中断后新进入的战斗不合并。完成提醒链接指向 `report.md`，使用客户端支持的绝对文件路径。已生成但未提醒的回放会在下次启动补发提醒。原始参数、审计和版本信息仅留在 `data/`。

Windows 短暂文件占用时，原子写入有限重试；清单持续被占用会告警并继续事件写入，后续心跳再次尝试。实际事件写入失败则明确告警。

### 文件用途

| 位置 | 用途 |
| --- | --- |
| `report.md` | 用户可读的 Markdown 回放 |
| `data/session.json` | 整局身份、开始结束时间、续跑分段清单 |
| `data/report.json` | 仅离线分析命令显式导出；客户端不重复保存 |
| `data/report_status.json` | 报告是否完成、是否已经提醒、处理异常 |
| `data/report_pending.json` | 未完成报告的待办标记，完成后移除 |
| `data/01/manifest.json` | 该运行分段的采集状态、截图设置、数量与缺口 |
| `data/01/events.jsonl` | 按时间追加的原始操作和观测，是重建报告的依据 |
| `data/01/frames/` | 开启截图记录时留存的画面；关闭时不创建图片目录 |
| `data/01/analysis/results.jsonl` | 一条结果流同时保存事件关联与识别结果；同画面引用复用，不再每图生成 JSON 和独立索引 |
| `data/01/analysis/status.json` | 同步识别状态与统计，用于判断报告是否完整 |

`01`、`02` 表示运行分段，不是第几场战斗。普通查看只需打开回放；其余文件是可追溯记录、续跑恢复和排错所需的数据。

客户端 OCR 复用当前 MaaFramework Context，不另建 Resource、Tasker 或识别进程；离线 CLI 才创建无输入识别环境。运行记录保留原始操作流、识别结果流、必要状态和可选截图。

奖励日志省略候选点击成功的重复 focus，保留进入奖励页面提示与领取详情；初/NIA 路线入口均提示进入事件页面。详情显示模板匹配、OCR 匹配和新增缓存数量。图标直接使用 MaaFramework TemplateMatch 匹配缓存模板，未命中或身份相近时才回退名称 OCR，不另实现相似度算法；学习时合并同身份的近似重复样本，写入索引后清理被替代或超出容量的已知图标。

截图由 MaaFramework 提供并以框架原生 PNG 编码保存，保留返回尺寸，不再二次缩放。奖励模板从 720×1280 图像按候选区域裁切，去掉外框但保留角标，不缩放为 64×64；缓存格式为第 4 版，旧缩略图不用于新匹配。

战斗截图只留操作前画面，下一次操作前画面同时作为上一操作的后续观察；图片和识别结果用引用复用，最后一次缺少后续画面时保留未知。战斗报告只展示操作前截图，不重复插入同图作为“操作后”。

### 奖励模板检索

复用奖励页面已识别的标题区分技能卡、饮料和 P 道具，只检索对应类别；类别未确认时检索全部有效模板。同名技能卡的普通及强化版本按家族合并为一次 MaaFramework 多模板调用，命中家族后再核验具体版本，版本间差距不足时回退名称 OCR。各版本身份和模板仍分别保留，不把普通版当作强化版。

预览命中后，读取器校验当前候选图像摘要、卡库版本和身份，复用匹配结果，不对同一候选再次执行模板检索。分类和分组不改变选择策略，也不降低匹配阈值。

## 本轮交付状态与后续工作

当前已实现文字常开、可选截图、同步识别、整局目录及续跑、自动 Markdown 回放和提醒、共享解析、奖励分类缓存及同卡变体分组。普通 Pipeline 节点未为记录改为 Custom。研究侧旧奖励效果重放工具及其运行时加载分支已移除，独立 ADB 采样链仍保留。

这是功能实现完成后的测试阶段，不代表最终验收完成。后续优先：
1. 按截图、框架识别、记录识别、查库、点击和等待分段测量实机出牌耗时，再决定优化位置；不改计时口径掩盖真实开销。
2. 验证初/NIA 完整轮次、连续多局、中断恢复、失败重试、活动四奖励及缓存复用，检查错误与回放缺口。
3. 保持强化、删除／复制／变换的操作记录，具体身份及实际效果未观测时不补造；新增更完整观察属于后续范围。
4. 明确研究数据的版本与可信范围，再开展基线比较；当前记录不自动成为策略训练数据。

不因本轮收尾自动同步 beta、增加刷局次数或发布。实测日志与耗时数据保存在实验目录，不写入业务常量。
