# 培育数据库与素材更新

“一键培育”最前面的“更新数据库和素材”默认启用，可以取消勾选。日文与汉化培育共用一次检查。服务地址默认为 `https://mag.2j.hk`；只更新技能卡、饮料、P 道具数据库、原始图标及来源和许可证说明。偶像任务配置、支援卡、战斗 HUD 模板、流水线和模型仍随客户端版本更新。

## 客户端行为

首次缺少图库时下载完整 ZIP。已有图片按 SHA256 复用，之后只下载新增、变化或损坏文件；增量大小达到整包大小时使用整包。无变化只检查清单，不重新下载数据库或图片。手工放入的上游原图同样参与复用。

正式数据继续放在 `data/`，图片直接位于 `data/images/skillCards/*.png`、`data/images/pDrinks/*.png`、`data/images/pItems/*.png`，不要再套 `icons/`。源码运行对应 `assets/data/`。更新不会改变图片像素、文件名、普通／强化版或偶像变体。

下载、续传文件、解压暂存和覆盖前备份位于 `temp/produce_update/<资源版本>/`。文件全部校验后才安装；安装成功后删除本次临时目录，正式目录只增加 `produce_resources_manifest.json` 和来源说明。不会创建多份正式版本目录，也不清理 MFA 的其他临时文件。

断网或校验失败会保留现有资源，提示后继续培育；断点文件可供下次续传。只删除上次成功清单管理、且新版移除的文件，其他手动文件保留。更新过程中取消任务会停止后续操作。存在活动培育会话时跳过更新；成功后清除内存图库缓存，同一 Agent 的下一轮直接生效。

覆盖期间短暂保存 `data/produce_resources_pending.json`。启动及培育入口先检查它，恢复未完成的安装；如果备份被外部清理且正式文件不完整，禁止开始新的培育，需重新执行更新在线修复。修复失败时不能继续使用混合版本。成功恢复／修复后标记自动删除。

MFA 的 [AppPaths](https://github.com/MaaXYZ/MFAAvalonia/blob/master/MFAAvalonia/Helper/AppPaths.cs) 使用安装目录下的 `temp/`；[MaaProcessor](https://github.com/MaaXYZ/MFAAvalonia/blob/master/MFAAvalonia/Extensions/MaaFW/MaaProcessor.cs) 当前只清理 `temp_mfa`、`temp_maafw`、`temp_res` 专用目录。培育更新使用独立子目录，并额外防御整个临时目录被手工清空的情况。

测试或迁移地址可创建 `config/produce_resources.json`：

```json
{
    "base_url": "https://mag.2j.hk"
}
```

生产地址必须使用 HTTPS；本地测试允许 `http://127.0.0.1:<端口>`。配置不存放凭据。更新代码在 `agent/produce/resources.py`，随 Agent 打包；客户端不依赖 `tools/` 或 Pillow。

## 云端部署

1. 在 Cloudflare 创建 Standard R2 Bucket，默认名 `maagakumasu-produce-resources`。Bucket 保持私有，不启用 `r2.dev`；Worker 通过绑定读取文件。
2. 将 `2j.hk` 域名接入同一 Cloudflare 账户。为发布创建仅允许访问该 Bucket 的 R2 读写凭据。
3. 在 GitHub 仓库 Variables 配置 `CLOUDFLARE_ACCOUNT_ID`；Bucket 改名时额外配置 `PRODUCE_R2_BUCKET`。Secrets 配置 `R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`。
4. 在 `cloud/produce-resources/` 执行 `npx wrangler@4 deploy`。`wrangler.jsonc` 已绑定 `mag.2j.hk` 和默认 Bucket，使用其他 Bucket 时同步修改配置。部署使用维护者自己的 Cloudflare 登录或 `CLOUDFLARE_API_TOKEN`，不把密钥写入仓库或客户端。
5. 先把工作流文件放到默认分支，让 GitHub Actions 显示 `Run workflow` 按钮。开发阶段运行 `Publish produce resources` 时，分支选择 `decision-capture`；该分支包含完整构建工具，main 暂时只有工作流入口。首次可手工填写上游完整小写 SHA，也可留空使用 `master`。当前暂不启用定时触发，功能完整合并到默认分支后再启用每日北京时间 08:00 检查。
6. 访问 `https://mag.2j.hk/v1/latest.json`，再下载对应清单和整包，核对客户端日志中的版本与哈希。用真实国内网络测试下载后再向用户开放。

独立工作流不修改客户端发布、安装或 Mirror 酱流程，也不会把完整图库加入客户端安装包。Actions 的 Pillow、boto3 仅用于维护构建。域名、Bucket 和 Secrets 配置完成前，客户端会提示更新失败并沿用现有资源。

## 发布协议与维护

Actions 从上游 `gakumas-tools/gakumas-tools` 的同一固定提交读取 `packages/gakumas-data/json/` 及 `packages/gakumas-images/images/{skillCards,pDrinks,pItems}/icons/`。只选原始 PNG，不使用 `gk-img` 的缩小 WebP，不包含详情大图。数据许可文件和来源说明随包保留。

校验包括数据结构、重复 ID、PNG 解码及尺寸、文件 ID 对应关系；缺图记录在来源说明的覆盖统计中，不把未知图标冒充为完整覆盖。源内容指纹不变则跳过发布。数据库的下载时间固定为上游提交时间，避免仅因每天运行而产生新版本。

| 接口 | 内容 |
| --- | --- |
| `/v1/latest.json` | 协议版本、资源版本、清单大小与 SHA256 |
| `/v1/releases/<版本>/manifest.json` | 来源、文件路径／大小／SHA256、完整 ZIP 信息 |
| `/v1/releases/<版本>/full.zip` | 初始完整包 |
| `/v1/objects/<SHA256>` | 增量文件 |

资源版本由规范化文件清单的 SHA256 决定。上传并校验所有不可变对象后，最后替换最新版指针；Worker 使用内容哈希作为 HTTP ETag，支持 GET、HEAD、条件请求及单段 Range。最新版响应要求重新验证缓存，固定版本文件长期缓存。

保留最近 14 个云端版本及其引用对象。回退时手工运行同一工作流，在 `rollback` 填资源版本，`revision` 留空；仅切换最新版指针，不改写旧版本。客户端不按版本号大小拒绝回退，会根据清单逐文件修复。

本地构建（输出放实验目录）：

```powershell
python tools/build_produce_resources.py --source <固定提交的上游检出目录> --output ../MaaGakumasuLab/debug/produce-resource-build
python research/produce/test_resources.py
node --test cloud/produce-resources/worker.test.mjs
```

构建输出目录应使用新的空目录。实际云端部署、R2 权限和网络可达性需要独立验收；本地合成回归不能证明云端配置或模拟器长流程正常。
