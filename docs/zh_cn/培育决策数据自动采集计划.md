# 培育决策数据自动采集计划

制定日期：2026-10-11。本文为待执行计划，不代表采集器已经实现或启动。

## 目标与范围

由 AI 完成运行环境定位、采集器开发、运行验证、自动识别、质量检查和报告生成。用户无需逐张截图或标注；无法可靠判断的信息保留为未知并进入待复核队列，不以猜测补齐。

第一阶段交付能够追溯一场战斗的决策记录；随后扩展为包含路线选择、选牌、购物、强化、删除、复制、变换、饮料及考试结果的全过程记录。架构支持多流派、不同偶像和等级，不要求高等级或关键牌齐全。

本阶段不训练策略、不更换现有选牌策略。现有自动操作是行为记录，不是最优动作答案。

## 已知现场与执行边界

- 用户报告 MuMu 已启动，MFA 正在执行培育。
- 本次检查仓库工作区无未提交修改；执行时必须重新检查。
- 本仓库没有 `debug/maa.log`；`debug/maafw.log` 最后记录为 2026-10-08，不能据此识别当前运行实例。
- 本次进程 CIM 查询不可用；当前 MFA 安装目录、实际加载资源、Agent 路径、ADB 设备与游戏画面均尚未确认。
- 计划编写期间未操作游戏，也未启动采集。

执行时优先利用当前任务。旁路采集只截图、读日志，不与 MFA 同时点击或启动另一套 Tasker。当前局标记为中途接入，缺失的开局信息保持未知。

不假定修改仓库文件能让已运行的 Python Agent 热更新。先确认加载生命周期，再在本局结束后的安全边界加载采集版本；不强杀当前培育。若无法在现有工具权限下定位或切换，只请求实际运行目录或必要的单次操作，不要求用户人工承担采集。

自动化只使用已配置的任务、账号和资源范围，不自行增加培育次数、开启体力药、付费购买或切换账号。培育商店的观察与记录不改变原有购买策略。

## 阶段 0：定位实际运行环境

1. 重读仓库协作规则、检查 Git 状态与相关 diff。
2. 通过可用的进程信息、客户端配置、最新日志和设备列表，确定 MFA、Agent、资源目录及 MuMu 实例；不输出 API Key 等无关配置。
3. 使用已安装 ADB 或框架截图能力获取原始游戏帧，核对实例、方向、尺寸与时间戳。出牌预期为 720×1280；实际不符时记录差异，不擅自旋转素材。
4. 核对剧本、难度、偶像及当前阶段；配置值与画面值分别保存，不能假定一致。
5. 检查截图通道延迟与磁盘余量，建立本次采集目录及运行清单。

产物：`manifest.json`，包含已确认来源、代码/资源版本、实际路径、设备标识、尺寸及未知项。验收：可以连续获得当前实例的新截图，并确认日志确实在更新；日志不可用时明确记录，不伪造关联。

## 阶段 1：当前这局进行旁路观察

1. 首先保存现有可用日志和起始截图引用，再短时试采，确认没有明显影响 MFA。
2. 从低频截图开始，依据实测延迟调整；场景变化时保存关键帧，必要时短时提高频率。周期截图不能保证捕获每次快速操作。
3. 根据日志、画面变化划分战斗、奖励、商店、强化等场景，生成时间线。
4. 旁路推断的操作使用 `inferred` 标记；日志直接支持的操作使用相应证据标记。缺少点击记录或前后画面时标记缺失，不补造成完整样本。
5. 当前局结束后自动生成可读报告，找出必须通过代码采集补足的信息。

当前局用途：建立画面样例、ROI 候选、识别难点与场景目录。不能承诺还原接入前路线、完整牌组或每一步精确出牌。

## 阶段 2：开发与接入事件采集器

拟新增独立采集模块，具体路径遵循执行时目录结构；优先复用现有截图与识别结果。

接入位置：`ProduceCardsAuto` 的候选识别、实际出牌、饮料处理、跳过及移动卡牌；再扩展自定义事件动作与相关流水线节点。原有 15 秒兜底、有效手牌区域过滤和推荐优先逻辑保持不变。

采集约定：

- 默认关闭，通过显式配置启用；若新增用户任务选项，同步中日任务定义及简繁翻译。
- 操作前记录状态与合法候选；操作发出时记录请求；操作后记录稳定画面与成功证据。
- 同一个出牌动作可能包含两次点击，区分逻辑动作与底层输入，不能记录成两次出牌。
- 通过手牌变化、状态变化、阶段变化等组合判断成功；输入 API 成功不等于游戏动作成功。
- 区分“动作后”“回合结束后”“下一次可决策时”，记录期间自动触发的效果，避免错配状态差值。
- 异步写盘使用有界队列，保存图像副本；溢出显式记录缺口，采集异常不阻塞主任务。
- 不恢复已移除的旧超时截图功能，另建用途明确的决策采集功能。
- 中途接入、游戏断连或采集器重启时创建分段，保留关联，不默认数据连续完整。

完整事件必须在实际加载了采集版本后验证；若客户端位于工作区外，先明确部署路径和写入权限，保留可回退版本。

## 数据格式

所有文件默认写入已忽略的 `debug/decision_capture/<run_id>/`，不提交截图和运行记录。

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 环境、数据模式版本、代码/卡库版本、采集范围与开始结束原因 |
| `events.jsonl` | 追加式事件、状态、候选、操作、证据和关联 ID |
| `frames/` | 去重后的原始截图，记录尺寸、时间戳与校验值 |
| `derived/` | OCR、卡牌匹配、Buff 识别、局面重建等可重新生成结果 |
| `review_queue.jsonl` | 低置信度、冲突、未知效果、缺帧与动作未确认样本 |
| `report.md` | 场景覆盖、完整率、未知率、性能及后续修复建议 |

关键字段：

- `run_id`、`battle_id`、`decision_id`、`event_seq`、墙钟与单调时间。
- 场景、剧本、难度、偶像、阶段、回合、属性、分数、体力、元气、Buff。
- 实际牌组与已知解锁信息，区分完整清单和部分观察；没有见过某牌不代表未解锁。
- 候选对象的实例 ID、卡库 ID、变体/改造、位置、可用性与识别证据。相同卡牌的多个副本须可区分。
- 饮料、P 道具、货币、购物价格、强化/删除等操作前后的变化。
- 选择来源：现有自动逻辑、人工或未来策略；操作请求、确认结果与失败原因。
- 每个识别字段的来源、置信度、截图引用与未知原因；原始观测与推断分开保存。

未发生或不可见的场景不制造记录；不可见 Buff 不写为零。中断接入时不假设完整牌组。

## 阶段 3：AI 自动识别与质量控制

1. 固定上游卡库快照与版本，保留原始效果字段，独立于现有偶像歌曲卡库。
2. 先用已有检测定位手牌，再结合 OCR、卡面局部匹配、已知牌组与强化标记匹配技能卡；保留多个候选，不强制猜唯一答案。
3. 逐步识别数字、Buff 图标/层数/持续时间、回合与场景；为官服/汉化和不同布局记录适配范围。
4. 使用时序一致性检查身份与状态，但未知触发效果不能被简单算术强行纠正。
5. AI 自动复查冲突截图与连续帧；仍有歧义时留在待复核队列，不输出为可信标签。
6. 本地原始截图默认不上传第三方；如执行环境允许 AI 直接查看本地图片，可用于疑难检查。新增外部识别服务需单独明确数据去向。

先标注局面和实际动作，不标注“最优动作”。后续模拟搜索评价另建版本化字段，不覆盖原始记录。

## 阶段 4：验证与扩展全过程

先完成打牌，再依次接入选牌奖励、培育商店、强化/删除/复制/变换、路线与结果。每个节点都验证候选、请求与实际变化的对应关系。

按流派、偶像固有机制、剧本/难度、等级与已知解锁条件统计覆盖。当前已配置任务能够遇到什么就先采集什么；不为了补齐矩阵擅自切换账号或耗费额外资源。

建议首轮验收目标（工程目标，非当前已达成结果）：

- 一场从开头采集的完整战斗可按顺序回放；中途接入样本单独统计。
- 操作事件序号、截图引用及文件校验通过；动作缺口和失败没有被静默丢弃。
- 至少 95% 的逻辑动作具备候选、操作前后证据和可判定结果；缺失项逐条列出，达不到时继续修复。
- 用独立复核的小样本评估牌名、变体、Buff 和数字字段正确率，不能只用识别器自报置信度验收。
- 对比启用前后的动作延迟与运行稳定性；原有出牌与超时行为无采集引起的回归。
- 未出现的购物、删除等场景标为未覆盖，不能据一场战斗宣称全过程验证完成。

代码检查按修改范围执行 compileall、相关脚本编译、JSON 格式与资源检查，并完成实机采集验证。临时测试遵循仓库 tests 目录清理规则。

## 自动运行、停止与恢复

- 采集器作为本地持续进程或 Agent 内模块运行，不依赖 AI 对话持续轮询；启动完成后输出进程、日志、状态文件及停止方式。
- 先短时试采并估算磁盘增长，再设置本次总量上限和最低可用空间。达到限制时只停止采集并报告，不删除已有素材。
- MFA 结束、设备断连、长时间无新帧或写盘失败时保存检查点与停止原因。避免无限重连或不断重复同一错误。
- 普通识别未知进入队列；阻断采集的异常才请求用户提供缺失信息。报告区分已确认、推断、未知和未覆盖。
- 当前任务结束后完成报告；无人值守扩展到后续轮次，需要明确任务次数和资源范围。需要对话关闭后的通知时再配置受支持的自动化，不以口头承诺代替运行机制。

## 交付与后续衔接

第一批交付：采集器、启停与状态机制、一场战斗记录、疑难样本队列和质量报告。随后交付全过程场景采集与覆盖报告。

数据达到可追溯标准后即可并行推进卡库匹配和模拟结算验证，无须等待大量样本。之后顺序为：多流派规则基线 → 可信模拟与搜索 → 构筑收益评价 → 视收益决定是否训练小模型。微调 LLM 或强化学习不属于本采集阶段的前置条件。
